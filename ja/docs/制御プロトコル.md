# コントロールプロトコル

デスクトップアプリは `127.0.0.1:<port>`（ループバックのみ）で待ち受ける。認証情報がプロセスのコマンドラインに露出しないよう、トークンファイルを指定して起動する。

```sh
photocraft --control 7878 --control-token-file /private/path/photocraft-control.token \
  --automation-read-root /work/project --automation-write-root /work/project
```

ファイルが存在しない場合、PhotoCraft は新しい 256 ビットのトークンでファイルを作成する。Unix では新規ファイルのモードは `0600` になる。Windows では、適切なユーザー専用 ACL で保護すること。既存のファイルはそのまま再利用される。トークンもトークンファイルも設定されていない場合、PhotoCraft はその起動用のトークンを生成して標準エラー出力に書き出す。環境変数で指定する場合は `PHOTOCRAFT_CONTROL_TOKEN` と `PHOTOCRAFT_CONTROL_TOKEN_FILE` を使う。

すべての TCP 接続で、最初のリクエストは認証でなければならない。これが成功するまで、他のメソッドは一切ディスパッチされない。

```json
{"id": "auth", "method": "auth", "params": {"token": "<64 hexadecimal characters>"}}
```

認証成功の応答の後は、各リクエストを 1 行の JSON で送る。

```json
{"id": 1, "method": "ui.inspect", "params": {}}
```

各応答は同じ `id` を持つ 1 行の JSON である。

```json
{"id": 1, "ok": true, "result": { ... }}
{"id": 2, "ok": false, "error": "unknown tool `foo`"}
```

トランスポートは `apps/photocraft/src/control_server.rs`、ハンドラーは `crates/ui-egui/src/control.rs` にある。MCP サーバー（`photocraft-cli mcp --bridge 127.0.0.1:<port>`、クレート `photocraft-automation`）はこれと同じプロトコルをラップしている。後述の [MCP ブリッジ](#mcp-bridge) を参照。

## メソッド

- `engine.execute {command, params}`: エンジンまたは UI の任意のコマンドを id で実行する。エンジンコマンドはデフォルトのパラメーターで直接実行され、ダイアログを開くことはない。メニューをクリックしたときの挙動が必要なら `ui.menu.invoke` を使う。こちらはパラメーターが与えられないとコマンドのダイアログを開く
- `engine.commands`: コマンドを有効状態とともに一覧する
- `ui.inspect`: UI の全状態（ツール、パネル、ビュー、ダイアログ、ウィンドウ、メニューツリー、ウィンドウサイズ）。`view` には表示／ウィンドウ／文字の設定が入る: `screen_mode`、`extras`、`show` と `snap_to` のフラグ、`flip_horizontal`、`arrange`（ウィンドウ › アレンジのレイアウト）、ピクセル縦横比、フォントプレビューのサイズ、言語オプション
- `ui.set {tool?, panels?, dockTabs?, dock?, dockWidth?, maskTarget?, zoom?, center?, fit?, theme?, brushSize?, brushSection?, brushTab?}`: UI 状態を変更する（`brushSection` はブラシ設定のセクションのインデックス、`brushTab` は 0 = ブラシ設定、1 = ブラシ。`dock` は `{order: ["layers", …], heights: {"properties": 180}, collapsed: ["color"]}` の形式で、右ドックのグループを上から順に、それぞれの高さ（ポイント単位）と、タブストリップに折りたたまれたグループを指定する。`dockWidth` は右ドックの幅をポイント単位で設定し、250..520 にクランプされる）
- `ui.menu.invoke {id}` / `ui.menu.list`: メニュー項目を id で実行する／メニューツリーを一覧する
- `ui.dialog.open {kind, fields?}`（kind は `newDocument`、`about`、`layerStyle {effect?}`、`colorPicker {target: foreground|background}`、`command {command}`） / `ui.dialog.set {dialog, field, value}` / `ui.dialog.confirm {dialog}` / `ui.dialog.cancel {dialog}`
- `ui.window.open {document?}` / `ui.window.close {window}`: 追加のドキュメントウィンドウ
- `ui.pointer {events: [{kind: down|move|up, x, y, pressure?, tiltX?, tiltY?, rotation?}], modifiers?}`: アクティブなツールをドキュメント座標で操作する（pressure は 0..1、tilt は -90..90 度、バレル回転は 0..360。ペンのシミュレーション）。`space: true` で Space キーを押した状態にする（切り抜きツールでは描画中の枠が移動する）
- `ui.key {key, command?, shift?, alt?, ctrl?}`（フラグは `modifiers` の下にまとめてもよい）: キーを押して離す。例: `{"key": "ArrowLeft", "shift": true}`
- `ui.type {text}`: テキストを入力する（フォーカスのあるウィジェットに入る。文字ツールで編集中ならキャンバスに入る）
- `ui.resize {width, height}`: メインウィンドウのサイズを変更する
- `ui.screenshot {path?, focus?}`: メインウィンドウをキャプチャする（PNG）。path がなければ応答に
  base64 の PNG データが含まれる。path はオートメーション書き込みルートからの相対パスである。macOS では
  隠れたウィンドウは描画を止めるため、デフォルトでは先にウィンドウを前面に出す
- `ui.focus`: メインウィンドウを前面に出す
- `app.open {path}` / `app.save {path}`: 設定されたオートメーションルートを介した相対パスのファイル I/O（`app.open` は読み取りルート配下を読み、`app.save` は書き込みルート配下に書く。絶対パス、`..`、ルートの外に出るパスは拒否され、ルートが許可されていなければどちらもフェイルクローズする）。どちらも `warnings`（「adjustment layer flattened」のようなインポート／エクスポート時の注記。なければ `[]`）を返し、これはステータスバーと通知（`ui.inspect` の `notices`）でもユーザーに表示される。`app.open` はさらに `path` とドキュメントの `name` を、`app.save` は書き込んだ `path` を返す。オートメーションによる開く・保存ではスクリプトイベントは発火しない。`file.open`、`file.save`、`file.saveAs`、`file.saveACopy` も同様に `warnings` を返す
- `app.quit`

## エンジンコマンド

`engine.execute` は任意のコマンドを id で実行する。`engine.commands`（またはエンジンコマンド `command.list`）は、ラベル、メニューパス、ショートカット、パラメーターの説明、現在有効かどうかとともにすべてのコマンドを一覧する。例:

| コマンド | パラメーター |
|---|---|
| `file.new` | `{"width":1920,"height":1080,"mode":"rgb","depth":8,"background":"white"}` |
| `layer.new.layer` | `{"name":"Ink"}` |
| `layer.select` | `{"layer":id,"mode":"replace\|toggle\|range\|add"}`: ⌘ クリック = toggle、⇧ クリック = range。`document.inspect` は `selectedLayers` とレイヤーごとの `selected` フラグを報告する |
| `channel.target` / `channel.setVisible` | チャンネルパネルのターゲットと目のアイコン（`"composite"`、カラー名、アルファのインデックスまたは名前、`"quickMask"`）。`document.inspect`（および `channel.list`）は `channels` を報告する: 表示状態とチャンネルオプションを持つ composite／カラー／アルファの各行、`quickMask`、`target`。`target` パラメーターを持たないピクセルコマンドは、ターゲットになっているチャンネルに従う |
| `layer.setProps` | `{"layer":id?,"name":…,"visible":…,"opacity":0..1,"blend":"Multiply"}` |
| `layer.setExpanded` | `{"layer":id?,"expanded":bool?,"all":bool?}`: レイヤーパネルでグループを開閉する（`expanded` なし: トグル、`all`: すべてのグループ）。ドキュメントに保存されるビューの変更（PSD のフォルダー開閉状態）であり、取り消しのステップにはならない。`document.inspect` はグループの `expanded` を報告する |
| `layer.newAdjustmentLayer.hueSaturation` | `{"hue":30,"saturation":10}` |
| `paint.stroke` | `{"points":[[x,y,pressure],…],"size":20,"color":"#ff0000"}` |
| `select.rect` | `{"x":0,"y":0,"width":100,"height":50,"mode":"add","ellipse":false}` |
| `document.inspect` | `{}`: レイヤーツリー、ヒストリー、選択範囲の境界 |
| `document.pixel` | `{"x":10,"y":10}`: コンポジットの RGBA |

UI レベルのコマンド（`file.open`、`file.save`、`view.zoomIn`、`window.theme.pro`、`edit.search` など）も `engine.execute` と `ui.menu.invoke` で受け付ける。

## 環境設定

環境設定（編集 › 環境設定。Photoshop のダイアログのセクションと同じようにグループ化されている）はエンジン内にあるため、
同じコマンドがアプリ、CLI、ヘッドレス MCP で動作する。パスはドット区切りの camelCase のキーで、
`<section>.<key>` の形式をとる。セクションは `general`、`interface`、`workspace`、`tools`、`historyLog`、
`fileHandling`、`export`、`performance`、`scratchDisks`、`cursors`、`transparencyAndGamut`、
`unitsAndRulers`、`guidesGridAndSlices`、`plugIns`、`type`、`enhancedControls`、`rawDefaults`、
`integrations` に加え、`shortcuts.<command id>`、`menus`（`hidden`、`colors.<id>`）、`toolbar`
（`hidden`、`order`）、`colorSettings`（編集 › カラー設定）がある。

| コマンド | パラメーター |
|---|---|
| `prefs.get` | `{"path":"performance.historyStates"}`。path がなければすべてを返す |
| `prefs.set` | `{"path":"cursors.painting","value":"precise"}` または `{"values":{"unitsAndRulers.rulers":"cm","guidesGridAndSlices.gridColor":"#ff8800"}}`。値は検証される（選択肢、範囲、`#rrggbb` のカラー、ショートカットの構文）。一括指定はすべて適用されるか、まったく適用されないかのどちらかである。セクションのパスにはオブジェクトを渡し、キーごとにマージされる |
| `prefs.reset` | `{"path":"performance"}`（セクションまたはキー）。path がなければすべてをリセットする |
| `edit.preferences.<section>` | そのセクションの値。アプリ内で（パラメーターなしで）実行すると、そのセクションで環境設定ダイアログを開く |
| `edit.keyboardShortcuts` | `{"set":{"edit.fill":"Cmd+Shift+F"},"reset":true\|["id",…],"removeConflicts":true,"filter":"blur","list":false}`: オーバーライド、一致するコマンド、競合を返す。別のコマンドに移したショートカットは、`removeConflicts` が false でない限り元の持ち主から削除される。`""` はショートカットを削除し、`null` はデフォルトに戻す。アプリ内ではキーボードショートカットとメニューを開く |
| `edit.menus` / `edit.toolbar` | `{"hide":["edit.fade"],"show":[…],"color":{"edit.fill":"red"},"reset":false}` / `{"hidden":["Sponge"],"order":[…]}` |
| `edit.colorSettings` | `{"workingRgb":"display-p3","workingCmyk":"coated-cmyk","workingGray":"sgray","policyRgb":"preserve\|convert\|off",…,"askOnMismatch":true,"intent":"perceptual","bpc":true}`。ファイルを開くとき（`file.openAs`、アプリのファイル › 開く）と、イメージ › モードおよび「作業用」プロファイル指定で使われる。`color.profileMismatch {"action":"preserve\|convert\|discard\|assignWorking"}` でプロファイル不一致の確認に応答する |

アプリが即座に反映する値: ヒストリー数（開いているすべてのドキュメント）、効果キャッシュの容量、インターフェイスの
テーマ、カンバスのカラーと境界、チェッカーボードのサイズとカラー（CPU と GPU のキャンバス）、色域外警告の
カラーと不透明度、ガイド／グリッド／スマートガイドのカラーとスタイル、グリッドの間隔と分割数、定規の
単位（定規、情報パネル、画像解像度のデフォルト単位）、画像補間方式（画像解像度のデフォルト）、
ペイントカーソルとその他のカーソル、スクロールホイールでズーム、Shift キーでツールを切り替え、キーボード
ショートカット、非表示や色付きのメニュー項目、自動保存の間隔とクラッシュからの復元、ヒストリー
ログのテキストファイル。GPU のオン／オフと GPU タイルサイズは次回起動時に反映される。

デスクトップアプリはこれらをプラットフォームの設定ディレクトリ内の `preferences.json` に保存する（macOS は
`~/Library/Application Support/Photocraft`、Windows は `%APPDATA%\Photocraft`、Linux は
`$XDG_CONFIG_HOME/photocraft`。`PHOTOCRAFT_CONFIG_DIR` で上書きできる）。自動保存はその
`Recovery` フォルダーに置かれる。Web ビルドは `localStorage` に保持する。

ユーザー作成およびインポートした（`.abr`）ブラシプリセットは、設定ディレクトリの `Presets` フォルダーに置かれる。
プリセットグループごとに 1 つの `.pcbrushes` JSON ファイル、`tips/` 配下にコンテンツアドレスで管理される先端ビットマップ、
グループの順序と削除された組み込みプリセットを記録する `index.json` からなる（`photocraft_engine::preset_store` を参照）。
ストアは起動時にバックグラウンドで読み込まれ、ブラシプリセットが変更されるたびに同期される。組み込みプリセットは
書き込まれない。ヘッドレスの CLI／MCP セッションと Web ビルドでは、ブラシプリセットはそのセッションの間だけ
保持される。グラデーションプリセット（インポートした `.grd` グループを含む）は環境設定とともに永続化される。

## スナップ

表示 › スナップがオンのとき、ツールのジェスチャーは表示 › スナップ先の対象（表示中のガイドとグリッド、
レイヤーの端と中心、ドキュメントの境界と中心、選択範囲の端）に画面上 8 ピクセル以内でスナップする。対象は、
移動ツールのドラッグ（移動するレイヤーの境界）、選択範囲、切り抜き、シェイプ、テキストボックス、ペンのポイント、
自由変形のハンドルとボックス内のドラッグ、ガイドである。Ctrl を押している間はそのドラッグのスナップが
無効になる。表示 › 表示・非表示 › スマートガイドがオンのとき、移動ツールは他のレイヤーにもスナップし、
マゼンタの整列線を描く。`ui.pointer` は同じコードを通るため、エージェントでも同一の結果が得られる。

## MCP ブリッジ

`photocraft-automation` は公式の Rust SDK（`rmcp`）で構築された MCP サーバーを提供する。次の 2 つのモードのいずれかで動作する。

- **ヘッドレス**（`photocraft-cli mcp`）: プロセス内の `photocraft_engine::Session`。ウィンドウはない。
- **ブリッジ**（`photocraft-cli mcp --bridge 127.0.0.1:7878 --control-token-file <path>`）: すべてのツールが、このプロトコル経由で実行中の `photocraft --control 7878 --control-token-file <path>` に転送されるため、エージェントは稼働中のアプリを見て操作できる。

ブリッジは認証済みの TCP 接続を 1 本開いたままにする。リクエストが失敗すると一度だけ再接続と再認証を行い、`id` がリクエストと一致しない応答行（たとえばタイムアウトしたリクエストへの古い応答）は読み飛ばす。アプリがループバックでしか待ち受けないため、ブリッジもループバックアドレスしか受け付けない。ベアラートークンは `--control-token-file`、`--control-token`、`PHOTOCRAFT_CONTROL_TOKEN_FILE`、`PHOTOCRAFT_CONTROL_TOKEN` のいずれかで渡す。

```sh
photocraft-cli mcp --bridge 127.0.0.1:7878 \
  --control-token-file /private/path/photocraft-control.token
```

ブリッジモードでの各 MCP ツールとコントロールメソッドの対応:

| MCP ツール | コントロールメソッド |
|---|---|
| `command_run {id, params}` | `engine.execute {command: id, params}` |
| `command_list {filter?, enabled_only?}` | `engine.commands`（MCP サーバー側でフィルタリング） |
| `doc_new {…}` | `engine.execute {command: "file.new", params}` |
| `doc_inspect` | `engine.execute {command: "document.inspect"}` |
| `doc_open {path}` | `app.open {path}` |
| `doc_save {path}` / `doc_export {path}` | `app.save {path}` |
| `doc_render_preview {max_side?}` | `ui.screenshot`。PNG 画像コンテンツとしてそのまま返す |
| `session_list`, `ui_inspect` | `ui.inspect` |
| `ui_screenshot {max_side?}` | `ui.screenshot`。PNG 画像コンテンツとして返す |
| `ui_pointer {events, modifiers?}` | `ui.pointer` |
| `ui_menu_invoke {id}` | `ui.menu.invoke` |
| `ui_set {fields}` | `ui.set` |
| `control_call {method, params}` | 任意のメソッド。変更せずにそのまま渡す |

`doc_select` と `doc_close` はヘッドレスモードでのみ動作する。`ui_*` ツールと `control_call` はブリッジモードでのみ動作し、ヘッドレスモードではブリッジモードの起動方法を説明するツールエラーを返す。

**セキュリティ上の注意:** TCP コントロールはベアラートークンを使うものであり、クライアントの識別やメソッドごとの汎用的な
認可は行わない。トークンを持つクライアントは、UI 入力、コマンド実行、アプリケーション制御を含む、
ファイルシステム以外のコントロール面全体を利用できる。トークンファイルは非公開に保ち、トークンを
コミットしたりログに出したりしないこと。プロセスのコマンドラインが見える共有システムでは、トークンを直接渡さないこと。
プロトコルは暗号化されておらず、ループバック上にとどめる必要がある。信頼できないホストへトンネルやプロキシで
転送してはならない。

ファイルシステムへのアクセスは、起動時に `--automation-read-root` と `--automation-write-root`（または
`PHOTOCRAFT_AUTOMATION_READ_ROOT` / `PHOTOCRAFT_AUTOMATION_WRITE_ROOT`）で読み取りルートや書き込みルートを
許可しない限り、フェイルクローズする。リクエストのパスは、該当するルート配下の、空でないスラッシュ区切りの相対パスで
なければならない。絶対パス、親ディレクトリへの移動、代替区切り文字、ドライブ／デバイス／ストリームの接頭辞、
不正な構成要素、リンクによる脱出は、ファイルへの作用が起きる前に拒否される。読み取り権限と書き込み権限は独立しており、
新しい出力ファイルの親ディレクトリはあらかじめ存在していなければならない。暗黙のファイルシステムパスをまだ使っている
エンジンコマンドは、同じケイパビリティインターフェイスに移行されるまでオートメーションからは無効になっている。
対話的なデスクトップのファイルピッカーは、ユーザーが選択した通常のアクセスを保持する。

## ヘッドレスサーバー

`photocraft-cli serve` はヘッドレスのエンジンセッションを 1 つ保持し（ウィンドウなし、GPU なし）、同じ
JSON-lines のエンベロープに標準入出力で応答する。`--port <port>` を指定すると `127.0.0.1:<port>` で応答する（ループバックのみ。
認証済みの各接続はセッションを共有する）。TCP では、デスクトップのコントロールと同じ最初のフレームでの `auth` 交換と
トークンのオプションを使う。標準入出力では、アクセス権がプロセスのパイプから継承されるため、この TCP ハンドシェイクは不要である。
スクリプトやエージェントが多数の編集を行うには最も速い方法で、MCP のフレーミングも、コマンドごとのアプリ起動もない。
ファイルアクセスは同じ `--automation-read-root` と `--automation-write-root` フラグで設定する。実装:
`crates/automation/src/rpc.rs`。

| メソッド | パラメーター |
|---|---|
| `engine.execute` | `{command, params?}`: 任意のエンジンコマンド |
| `engine.commands` | `{filter?}`: パラメーターの説明と有効状態を含むレジストリ |
| `session.list` | 開いているドキュメントとアクティブなインデックス |
| `doc.open` / `doc.new` | `{path}` / `file.new` のパラメーター |
| `doc.save` | `{path?, format?, quality?, index?}`（`.pcraft` はネイティブ保存、それ以外は拡張子に応じて書き出し） |
| `doc.inspect` | `{index?}`: `document.inspect` と同じ JSON |
| `doc.render` | `{index?, maxSide? (1024; 0 = full), path?}`: `path` に PNG を書き出す。なければ `{mime, base64}` |
| `doc.select` / `doc.close` | `{index}` / `{index?}` |
| `batch` | `{steps: [{command, params?} \| {method, params?}], stopOnError? (true)}` → `{completed, failed, results}` |
| `methods` | 上記の一覧 |

```sh
printf '%s\n' \
  '{"id":1,"method":"doc.open","params":{"path":"in.jpg"}}' \
  '{"id":2,"method":"batch","params":{"steps":[{"command":"image.adjustments.invert"},{"command":"filter.blur.gaussianBlur","params":{"radius":3}}]}}' \
  '{"id":3,"method":"doc.save","params":{"path":"out.png"}}' | \
  photocraft-cli serve --automation-read-root /work/project --automation-write-root /work/project
```

MCP サーバーも `command_batch` ツール（`{steps:[{id, params}], stop_on_error}`）で同じバッチ処理を、
ヘッドレスモードとブリッジモードの両方で提供する。

## トランスポートの制限

デスクトップとヘッドレスの TCP リスナーは現在、次の制限を課している。

- エンコード済みリクエスト行の最大サイズは 1 MiB
- エンコード済み JSON 応答の最大サイズは改行を含めて 8 MiB
- リスナーあたり同時に処理する接続は最大 16
- ソケットの読み書きタイムアウトは 30 秒
- ヘッドレスの `batch` または MCP の `command_batch` リクエストのステップ数は最大 256

サイズ超過の行、上限を超えた接続、未認証のリクエスト、許可されていないファイルシステムパスは、
コマンドのディスパッチやファイルへの作用の前に拒否される。ヘッドレスの JSON-lines 標準入出力サーバーも
リクエストと応答のバイト上限を課す。MCP ツールの結果は、テキスト／画像コンテンツのエンベロープを含めた
エンコード済み JSON として検査され、MCP ブリッジはデスクトップから受け取る応答のサイズを制限する。

ヘッドレスのオートメーションプレビュー（`doc.render` / MCP の `doc_render_preview`）では、要求できる最大辺は
2048 ピクセル、元ドキュメントは最大 67,108,864 ピクセルである。`maxSide: 0`（MCP では
`max_side: 0`）は引き続きフルサイズを意味するが、ドキュメントの長辺が 2048 を超えると失敗する。
PNG の結果は、base64 エンコードやファイルへの書き出しの前に 5 MiB に制限される。プレビューの
寸法／元画像のチェックはコンポジットの前に、エンコード済み PNG のチェックはエンコードの後に行われる。
明示的な信頼済みローカル CLI の描画は従来どおりの挙動を保つ。

バッチの応答には、外側の応答と ID のための領域を確保した合計バイト数の上限がある。
これを使い切ると、`stopOnError` が false でも以降のステップは停止する。編集が実行された後に結果が
応答の上限を超えることもあり、その場合のエラーは操作が完了している可能性があることを示す。先行するステップは
ロールバックされないため、再試行の前に状態を検査すること。MCP ブリッジはサイズ超過の応答を受け取ると、
操作を自動で再試行せずに破棄する。ブリッジ経由のスクリーンショットは、縮小しない場合でも、
辺 8192 ピクセル、16,777,216 ピクセル、64 MiB の割り当て上限でデコードされる。

これらの上限は、明示的な JSON の深さポリシー、セッション／ドキュメントのメモリ総量の計上、
コンポジターの作業領域の計上、コマンドのキャンセル／実行時間の制限、メソッドごとの汎用的な
ケイパビリティを実装するものではない。デスクトップのスクリーンショットのキャプチャ／エンコードと、ドキュメントのインポート／エクスポートには、
まだそれぞれの処理予算が必要である。デスクトップの応答上限は UI が応答を生成した後に適用される。
出力が制限されていても、コマンドのコストが制限されているとは限らない。
