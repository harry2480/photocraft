# コントリビューション

- **言語：** Rust のみ。JavaScript や TypeScript は使わない。Web では `wasm-bindgen` が小さなローダーを生成する。JS を手書きしてはならない。
- **ライセンス：** コントリビューションは MIT OR Apache-2.0 とする（`LICENSE-MIT`、`LICENSE-APACHE`、`NOTICE`）。`docs/brand/` にある ArtCraft のロゴはオープンソースではない（`docs/brand/LICENSE-brand.txt`）。
- **クリーンルーム：** プロプライエタリなソフトウェア（Photoshop など）からコード、シェーダー、アイコン、ICC プロファイル、その他のアセットをコピーしてはならない。振る舞いと見た目は、観察と公開仕様に基づいて合わせる。寛容なライセンスのアセットのみを使い、そのライセンスをアセットの隣に置き（例：`assets/fonts/OFL-*.txt`、`assets/icons/LICENSE-lucide.txt`）、すべてのアセットを `ATTRIBUTION.md` に記載する。
- **決してクラッシュさせない：** テスト以外のコードはパニックしてはならない。`unwrap`/`expect`/`panic!`/`unreachable!`/`todo!`/`unimplemented!` も `unsafe` も使わない。エラーは `Result` と `?` で扱い、入力に由来するインデックスやサイズはチェックし、クラッシュの修正には必ず回帰テストを付ける。`AGENTS.md` の *Never crash* を参照。
- **ハンドラーではなくコマンド：** 新機能はテスト付きのエンジンコマンドとして実装し、UI はそれを呼び出す（下記のチェックリストを参照）。
- **レイヤリング：** `cargo xtask layers` が通らなければならない。新しいクレートは `xtask/src/layers.rs` に登録する。
- **テスト：** すべての変更に必須。フォーマット関連のコードにはラウンドトリップと不正入力のテストが必要。ピクセルを扱うコードは 8、16、32 ビットでテストする。
- **スタイル：** `cargo fmt` と `cargo clippy -- -D warnings`。周囲のコードに合わせる。コメントには *なぜ* を書く。
- **UI：** `theme::Tokens` と `widgets::*` を使う。提出前に視覚的に確認し（オフスクリーンの `snapshot` サンプルまたはコントロールチャンネル）、PR には変更前後のスクリーンショットを添付する。
- **コミット：** 小さく、焦点を絞り、明確な件名を付ける。

## コマンドの追加

1. **id を見つける。** `crates/ui-egui/src/menu_catalog.rs` で Photoshop のメニュー項目を検索する。その id を使えば、UI 側の作業なしでメニュー項目が有効になる。Photoshop のメニューに存在しないコマンドは、同じスタイルの説明的な id（`layer.smartFilter.delete`）と空のメニューパスを使う。
2. **アルゴリズム** は、適合する最も低いクレート（画像処理なら `algo`、`paint`、`vector`、`text`、`cms`）にユニットテストとともに置く。深度に依存しないサーフェス（`photocraft-raster`）を受け取り、タイルごとに処理し、決定的（シード付きの乱数）であること。
3. **コマンド** は `specs()` を公開するエンジンのモジュール（`crates/engine/src/<area>_cmds.rs`）に置き、`commands.rs` で `v.extend(...)` により登録する。次の項目を埋める。
   - `id`、`label`、`menu` パス、Photoshop のデフォルトの `shortcut`
   - `{"radius":px=4,"mode":"a|b"="a"}` のような params のドキュメント文字列（エージェントが `commands` / `command_list` を通じて読むのはこれである）
   - `enabled` 述語（メニュー項目をグレーアウトする）
   - `run`。JSON の結果を返し、ヒストリーのステップをちょうど **1 つ** 記録する（ドラッグや入力のセッションには `coalesce` を使う）
4. **コンテキストを尊重する：** アクティブな選択範囲（ぼかしを含む）、レイヤーとマスクのどちらが対象か、ロック、カラーモデルと深度。
5. **テスト** をモジュール内に書く：振る舞い、アンドゥ／リドゥ、無効状態、不正なパラメータ、複数の深度。
6. **ダイアログ**（パラメータがある場合）：フィルターと色調補正には、ライブプレビュー付きのスキーマ駆動ダイアログを用意する（`ui-egui/src/filter_dialog.rs`、`dialogs.rs`）。
7. `cargo xtask parity` を実行し、更新された `docs/parity.md` をコミットする。
