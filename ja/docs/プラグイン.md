# プラグイン：WebAssembly プラグイン API（ABI v1）

PhotoCraft はネイティブの Photoshop プラグイン（`.8BF`、CEP、UXP）をホストしない。それには任意のマシンコードへの
unsafe な FFI が必要であり、ブラウザ版では動作しないためである。代わりに、プラグインはサンドボックス内で実行される **WebAssembly
モジュール** である。1 つの `.wasm` ファイルが macOS、Windows、Linux、Web で動作する。

このページはプラグイン作者向けの契約であり、ホスト側
（`crates/plugins`、`crates/engine/src/plugin_cmds.rs` 内の `plugin.*` コマンド）のリファレンスである。

## プラグインの使い方

| コマンド | パラメータ | 動作 |
|---|---|---|
| `plugin.install` | `{"path": "/x/y.wasm"}`（ネイティブ）または `{"data": "<base64>"}`、`"replace": bool = true` | モジュールを検証してインストールし、その説明を返す。 |
| `plugin.list` | `{}` | `{"plugins": [{id, name, version, kind, author, description, params, paramsSchema, overlap, area, size, source}], "folder": report}` |
| `plugin.run` | `{"id": "…", "params": {…}}`（プラグインのパラメータはトップレベルのキーとして渡してもよい） | アクティブなピクセルレイヤー、対象のアルファチャンネル／クイックマスク、またはスマートオブジェクトに対してフィルタープラグインを実行する。取り消しは 1 ステップ。 |
| `plugin.remove` | `{"id": "…"}` | アンインストールする。 |
| `plugin.reload` | `{"path": "folder"}`（デフォルト：環境設定のフォルダー） | フォルダー内のすべての `*.wasm` を読み込む。不正なモジュールは報告してスキップする。 |

アプリ内では、インストールされたフィルターは **フィルター › Plug-ins** の下、**Install Plug-in…** の隣に表示される
（パラメータを持つ場合は、生成されたダイアログとライブプレビュー付き）。

**環境設定のフォルダー。** 編集 › 環境設定 › プラグイン › *Use Additional Plug-ins Folder* と
*Additional Plug-ins Folder*：両方が設定されている場合、そのフォルダー内のすべての `*.wasm`（再帰なし）が、
起動時および設定が変更されるたびにインストールされる（ネイティブビルドのみ。Web ビルドはバイト列から
インストールする）。

プラグインはドキュメント単位ではなく **プロセス単位** でインストールされる。プラグインから記録された
スマートフィルター（`{"command": "plugin.run", "params": {"id", "params"}}`）は、そのプラグインがインストールされている間は
再レンダリング時に再実行される。プラグインがない場合、そのフィルターはスキップされ（キャッシュされたピクセルはそのまま残る）、
PhotoCraft が実装していない他のフィルターと同じ扱いになる。

## サンドボックス

ホストは [`wasmi`](https://github.com/wasmi-labs/wasmi)、純 Rust の WebAssembly インタープリタ
（MIT OR Apache-2.0）である。これは `wasm32-unknown-unknown` 向けにもビルドできるため、プラグインは Web
ビルドでも動作する。制限（`photocraft_plugins::Limits`、デフォルト値）：

| 制限 | デフォルト | 違反時 |
|---|---|---|
| ホストのインポート | なし：WASI、ファイルシステム、ネットワーク、時計、乱数はいずれもなし | インストール時にモジュールを拒否 |
| モジュールサイズ | 32 MiB | 拒否 |
| 線形メモリ | インスタンスあたり 512 MiB | `memory.grow` が -1 を返す。過大な初期メモリは失敗 |
| 命令数（fuel） | 呼び出しあたり 5,000 万 + `pc_filter` ではサンプルあたり 4,000 | `Limit("instruction budget")` |
| 実時間 | 実行あたり 60 秒（ネイティブ。2,000 万命令ごとにチェック） | `Limit("time budget")` |
| 呼び出しの深さ | 1,024 フレーム | トラップ |
| モジュールの形状 | wasmi の厳格な制限（関数 ≤ 10,000、メモリ 1 つ、…） | 拒否 |

各バンドは **新しいインスタンス** で実行されるため、呼び出し間で状態は残らず、並列のバンドが
メモリを共有することもない。トラップ、予算の枯渇、不正なモジュール、不正なマニフェスト、範囲外の
ポインタ、ゼロ以外の戻り値はすべてエラーとなり、ドキュメントは変更されない（編集は
トランザクショナルである）。NaN や無限大の出力サンプルは元の値を保持する。整数深度の
ドキュメントとアルファは 0–1 にクランプされる。

wasmi は *ポータブル*（ループ）ディスパッチャでビルドしている。デフォルトの末尾呼び出しディスパッチャは LLVM の
兄弟呼び出し最適化に依存しており、それが効かない場合、長時間実行されるモジュールがホストの
スタックをオーバーフローさせ、エラーを返すのではなくプロセスを異常終了させてしまうためである。

## ABI v1

プラグインはコア WebAssembly モジュール（MVP + 一般的な MVP 後の機能：バルクメモリ、符号
拡張、マルチバリュー、飽和変換。SIMD と memory64 はなし）であり、**インポートを持たず**、以下を
エクスポートする。特記がない限り整数はすべて `i32` で、ポインタはモジュールのメモリ内のオフセットである。

| エクスポート | シグネチャ | 意味 |
|---|---|---|
| `memory` | memory | モジュールの線形メモリ。 |
| `pc_abi_version` | `() -> i32` | `1` を返さなければならない。 |
| `pc_manifest` | `() -> i64` | UTF-8 のマニフェスト JSON（≤ 64 KiB）の `(len << 32) \| ptr`。 |
| `pc_alloc` | `(size) -> ptr` | ホストが書き込める `size` バイトのブロック、失敗時は `0`。解放されることはない：各バンドは新しいインスタンスを得る。 |
| `pc_filter` | `(buf, buf_len, width, height, channels, format, params, params_len) -> i32` | ピクセルをその場でフィルター処理する。`0` = 成功、それ以外はエラーコード。 |

### マニフェスト

```json
{
  "id": "org.example.tone",
  "name": "Tone…",
  "version": "1.0.0",
  "kind": "filter",
  "author": "Example",
  "description": "What it does.",
  "params": {
    "amount": {"type": "number", "min": 0, "max": 100, "default": 50},
    "steps":  {"type": "int", "min": 1, "max": 16, "default": 4},
    "mono":   {"type": "bool", "default": false},
    "mode":   {"type": "choice", "options": ["soft", "hard"], "default": "soft"}
  },
  "overlap": 0,
  "area": "content"
}
```

- `id`：`A-Z a-z 0-9 . _ -` からなる 1–64 文字（逆ドメイン形式を推奨）。同じ id のモジュールを
  インストールすると古いものが置き換えられる。
- `name`：メニューのラベル（1–64 文字の印字可能文字）。`kind`：`"filter"`（v1 で唯一の種類）。
- `params`：ダイアログでの表示順。名前は `[A-Za-z0-9_]` で、`_` で始まらず、`id`/`layer` でもないこと。
  ホストは呼び出し前にユーザーの値を検証する：値がなければデフォルトを使い、数値は
  `min..max` にクランプし（int は丸める）、型の誤りや未知の choice はエラーとする。
- `overlap`（0–256）：フィルターが各出力ピクセルの周囲に必要とする文脈のピクセル数（ぼかしの半径）。
  ホストは各バンドの全辺を `overlap` だけパディングし、カンバス（またはカンバス外のレイヤー内容）の端のピクセルを
  繰り返して埋め、結果の内側の矩形だけを残す。
- `area`：`"content"`（デフォルト）はレイヤーの非透明領域の境界を `overlap` だけ広げた範囲をフィルター処理する。
  `"canvas"` は透明ピクセルも含めたカンバス全体をフィルター処理する（ジェネレーター向け）。

### ピクセル

`buf` は `width × height × channels` 個の **リトルエンディアンの `f32` サンプル** をインターリーブ、行優先で保持し、
どのビット深度でも 0–1 に正規化されている（32 ビットのドキュメントは 1 を超える値を持つことがある）。バッファは
オーバーラップの余白を含めて `width × height` である。チャンネルはドキュメント自身のカラーモデルであり、
変換は行わない：

`format` = `depth | alpha << 8 | mode << 16`

- `depth`（ビット 0–7）：ドキュメントのビット深度、8、16、32 のいずれか（参考情報：サンプルは常に `f32`）。
- `alpha`（ビット 8）：最後のチャンネルが（プリマルチプライドではなくストレートの）アルファである場合に 1。
- `mode`（ビット 16–23）：カラーモード。PSD ファイル形式と同じ番号付け：0 Bitmap、1 Grayscale、
  2 Indexed（RGB として格納）、3 RGB、4 CMYK、7 Multichannel、8 Duotone（グレーとして格納）、9 Lab。

アルファチャンネルとクイックマスクの対象は、1 つのグレースケールチャンネルとして渡される。

ホストはレイヤーをバンド（タイル境界に揃えた、`f32` で最大約 4 MiB のブロック）に分割し、ネイティブビルドでは
並列に実行し、結果をレイヤーのフォーマットで書き戻してから、選択範囲とブレンドする：
`out = original + (filtered − original) × coverage`。これは組み込みフィルターとまったく同じである。
プラグインが選択範囲を見ることはなく、選択範囲に対応するために特別なことをする必要もない。

### パラメータ

`params` は `params_len` バイトの UTF-8 JSON を指す。内容は検証済みのパラメータに加え、
バンドのジオメトリを持つ `_image` である：

```json
{"amount": 50, "mode": "soft",
 "_image": {"x": 0, "y": 256, "width": 1024, "height": 256, "overlap": 0,
            "canvasWidth": 6000, "canvasHeight": 4000,
            "mode": "rgb", "depth": 8, "alpha": true, "channels": 4}}
```

`x, y` はバッファ左上のサンプル（余白を含む）のドキュメント上の位置であるため、
位置に依存するフィルター（グラデーション、周辺減光）もバンドをまたいで継ぎ目なく処理できる。

## Rust でプラグインを書く

[`examples/plugins/invert-rs`](../examples/plugins/invert-rs) は完全な `no_std` プラグインである
（アロケータなし、ビルド後 1 KiB 未満）。次のようにビルドする：

```sh
rustup target add wasm32-unknown-unknown
examples/plugins/invert-rs/build.sh      # cargo build --release --target wasm32-unknown-unknown
```

このスクリプトは、そのソースからビルドされるテストフィクスチャ `crates/plugins/tests/fixtures/invert.wasm` も更新する。
モジュールがインポートを持たない限り、コア WebAssembly をターゲットにできる言語なら何でも使える（C、Zig、AssemblyScript、WAT…）。
Rust の場合、それは `no_std` か、WASI に一切触れない `std` ビルドを意味する。

## 性能

インタープリタは命令あたりおよそネイティブの 10–100 倍のコストがかかるため、プラグインはピクセル単位や
小さな近傍を扱うフィルターに向いている。バンドが並列に実行されるため、例の Invert を 6000 × 4000 の
RGBA 8 ビットレイヤー（24 MP、リリース、高負荷下の 14 コア Apple Silicon）に `plugin.run` で適用すると
1.1–1.6 秒かかった。これに対し、（シングルスレッドの）組み込みの イメージ › 色調補正 › 階調の反転 は 3.6–5.1 秒だった
（`cargo run --release -p photocraft-engine --example bench_plugin_invert`。プラグイン単体：
`cargo run --release -p photocraft-plugins --example bench_invert`）。追加のピークメモリはワーカースレッドあたり約 3 バンド分
（入力、選択範囲ブレンド用のオリジナル、インスタンスのメモリ）、つまりスレッドあたり約 12 MiB である。

## v1 に含まれないもの

- パネル／UI プラグイン、他のレイヤーやドキュメントを読むプラグイン、ホストのコールバック（進捗、
  キャンセル）、プラグインが提供するファイル形式。
- フィルター › 前回のフィルター は、まだプラグインの実行を繰り返さない。
