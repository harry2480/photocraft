テスト数、そして下の[正直なパリティ評価](#honest-parity-assessment-2026-10-05)と合わせて読んでください。

## 正直なパリティ評価（2026-10-05）

これは「Photoshop パリティに実際どこまで近づいているのか」に対する基準となる答えです。エージェントは
作業を選ぶ前に読んでください。数値が動いたら（日付付きの計測値で）更新してください。代わりにメニューパリティの
数値を書き直すことはしないでください。

**結論。** 0.2.0 から 2 日で約 96 件の PR をマージし、約 48 件の Issue をクローズしましたが、**実際の
Photoshop パリティはまだ 50% を大きく下回っています**。最大のギャップは AI、欠けているツール、プロの
ワークフローの深さ、プラグインのエコシステムです。0.2.0 以降の修正のほとんどはテストを通過していますが、
**まだユーザーによる検証は済んでいません**。そして今週、テストではユーザーが遭遇する問題を見逃すことが証明されました。
最初の一般利用で、ユーザーは基本的な不具合（テキスト選択位置のずれ、214 件のショートカットの失敗、パネルが
勝手にリサイズされる、切り抜き枠が動かせない、フォルダーが折りたためない、レイアウト PSD での遅延）を見つけましたが、
これらはすべて `parity.md` では「稼働中」として数えられていました。

**全体。** 機能の範囲: 一般的な Photoshop ユーザーが触れる機能のおよそ **60〜70%** が何らかの形で
存在します。「プロが日常業務で乗り換えられる」かどうか: およそ **25〜35%**。真の 1:1 パリティには
**何か月も**集中した作業が必要で、一部の領域は労力よりも製品としての判断を必要とします。
確度: 中程度 — 0.2.x の次のユーザーたちによって、これらの数値はどちらの方向にも動くでしょう。

### 今後の方向性（優先順）

1. **修正を出荷する:** 現在のバッチが入ったら 0.2.1 を作成し、ユーザーに検証してもらう。
2. **PSD の忠実度を 170/170 に**、ラウンドトリップも含めて。加えて、スマートフィルター、文字エンジン、
   効果シェイプ用の Photoshop で作成したリファレンスセットを用意し、`corpus.rs` で下限値を強制する。
3. **ワークフローの受け入れテスト:** 30〜50 個の現実的なタスク（ポートレートのレタッチ、テキストと
   効果を使った SNS 投稿、マスクと調整レイヤーを使った合成、CMYK の印刷準備…）をエンドツーエンドでスクリプト化し、
   毎ビルドで Photoshop の出力と照合する。その合格率を代表的なパリティの
   数値とする。
4. **欠けているツール**、まずはペンのバリエーションとパス選択（ダイレクト選択）、パッチ / コンテンツに応じた
   移動、鉛筆、回転ビュー、遠近法の切り抜きから。
5. **複雑なドキュメントのパフォーマンス**（#125/#128）とテクスチャ上限を超える GPU タイル分割（#49）。
6. **定期的な目視 QA**（`cargo run -p photocraft-engine --example designer_psd`）と、ユーザー報告への
   迅速な対応（OS、ドキュメントサイズ、レイヤー数、スクリーンショット）。
7. 後日 / 判断が必要なもの: 生成 AI バックエンド（#41）、スクリプトの互換性（ExtendScript /
   UXP / .atn）、Flathub（#173）、macOS/Linux のペン筆圧（#79）。
