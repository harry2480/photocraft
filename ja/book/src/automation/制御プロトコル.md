# 制御プロトコル

デスクトップの制御プロトコルは、`127.0.0.1` にバインドされた TCP リスナー上の改行区切り JSON である。すべての接続で、最初のフレームは設定済みの 256 ビットのベアラートークンを伴う `auth` でなければならない。認証後、各リクエストは `id`、`method`、および任意の `params` を持ち、各レスポンスは対応する `id` と、結果またはエラーのいずれかを含む。

```json
{"id":"auth","method":"auth","params":{"token":"<64-hex>"}}
{"id":1,"method":"ui.inspect","params":{}}
```

現在のメソッドカタログには、エンジンの実行と探索、アプリケーションのオープン／保存操作、UI の検査と入力、スクリーンショット、ドキュメント／制御のヘルパーが含まれる。正となるメソッドとパラメータの表は [`docs/control-protocol.md`](https://github.com/storytold/photocraft/blob/main/docs/control-protocol.md) で管理されている。

実装は次のように分かれている。

- `apps/photocraft/src/control_server.rs`: ループバック TCP トランスポート
- `crates/ui-egui/src/control.rs`: 稼働中アプリケーションのハンドラ
- `crates/automation/src/bridge.rs`: MCP から GUI へのクライアント

## 現在のセキュリティ態勢

**Implemented（実装済み）:** デスクトップサーバーは IPv4 ループバックにバインドする。すべての TCP 接続は
ディスパッチ前に認証される。ブリッジはループバック形式のアドレスのみを受け付け、接続時に認証する。
エンコード済みリクエスト行は 1 MiB に制限される。アクティブな接続は 16 に制限される。
ソケット I/O とハンドラの待機にはタイムアウトがある。MCP とヘッドレスのバッチは 256 ステップに制限される。
JSON-lines のレスポンスとエンコード済み MCP ツール結果は 8 MiB が上限で、バッチ全体のレスポンスにも
予算が設けられている。ヘッドレスのプレビューには、ソースピクセル数、要求辺長、エンコード済み PNG の上限がある。
ブリッジは受信するレスポンスフレームとスクリーンショットのデコードを制限する。
自動化のファイルメソッドには、個別に設定された読み取りルートと書き込みルートが必要である。リクエストのパスは
相対パスであり、絶対パス、トラバーサル、代替区切り文字、デバイス名、リンクによる脱出を含むパスは
ファイルへの作用が起きる前に拒否される。

**Known limitations（既知の制限）:** トークンはベアラー資格情報であり、ファイルシステム以外の
制御面全体へのアクセスを付与する。暗号化、クライアント識別、汎用的なメソッド単位のケイパビリティチェック、
明示的な JSON 深さポリシー、セッション全体のメモリ計上、コマンド実行時間／キャンセルの予算はいずれも存在しない。
デスクトップのキャプチャ／エンコードとインポート／エクスポートには、それぞれ独自の操作予算がまだ必要である。
リスナーは、接続数上限の範囲内で、認証済みのアクティブな接続ごとに 1 スレッドを生成する。
信頼された単発の CLI 操作と対話的なデスクトップのファイルピッカーは、起動したユーザーの通常の
ファイルシステム権限を保持する。

非公開のトークンファイルを使い、`--control` は信頼できるローカル自動化セッションでのみ有効にし、暗号化されていないこのプロトコルをループバックの外へプロキシしてはならない。残っているゲートウェイの作業については [自動化のセキュリティ](../security/自動化のセキュリティ.md) を参照のこと。
