# 自動化のセキュリティモデル

自動化リクエストは信頼できない入力であり、アクティブなドキュメントを越えた影響を及ぼしうる。オープン、保存、パスへのレンダリング、環境設定の変更、アプリケーション制御、ポインタ／タイプ入力の注入、任意のエンジンコマンドは、それぞれリスクの水準が異なるが、現状では広範なトランスポートアクセスを共有している。

| 制御策 | 現在の状況 |
|---|---|
| ループバック限定の TCP バインド | デスクトップ制御とヘッドレス TCP serve で **Implemented（実装済み）** |
| stdio トランスポート | MCP とヘッドレス JSON lines で **Implemented（実装済み）** |
| コマンドレベルのエラー処理 | **Implemented（実装済み）**。コマンド固有のテストと `panic_hunt` によるカバレッジあり |
| 制御チャネルの認証 | **Implemented（実装済み）:** TCP のメソッドディスパッチ前に 256 ビットのベアラートークンが必要 |
| MCP のケイパビリティスコープ | **Partial（部分的）:** ファイルシステムの読み取り／書き込みケイパビリティのみ。汎用的なツールスコープはない |
| 許可された読み取り／書き込みルート | **Implemented（実装済み）:** 起動時に個別のルートを指定し、権限がない場合はフェイルクローズ |
| シンボリックリンクに安全なケイパビリティファイルシステム | **Implemented（実装済み）:** 相対操作は保持したディレクトリケイパビリティを使い、リンクによる脱出を拒否 |
| リクエストバイト数と JSON 深さの制限 | **Partial（部分的）:** リクエスト行は 1 MiB に制限。明示的な JSON 深さポリシーはない |
| バッチステップ数の制限 | **Implemented（実装済み）:** ヘッドレスと MCP のバッチで 256 ステップ |
| レスポンスサイズの制限 | **Implemented（実装済み）:** エンコード済み JSON／MCP 結果は 8 MiB。バッチ全体のレスポンス予算あり |
| ヘッドレスプレビューの予算 | **Implemented（実装済み）:** 要求辺長 2048 ピクセル、ソース 67,108,864 ピクセル、エンコード済み PNG 5 MiB |
| 接続／ワーカー数の制限 | **Implemented（実装済み）:** アクティブな TCP 接続は 16。受け付けたアクティブ接続ごとにワーカースレッド 1 つ |
| セキュリティ監査イベント | **Proposed（提案）** |

## ゲートウェイの状況と残作業

```text
MCP or control client
          |
 authenticated session
          v
 security gateway
   - general method capabilities (proposed)
   - path handles/read-write roots (implemented)
   - request budgets
   - command policy
   - audit events
          |
          v
 command engine / UI shell
```

現在のトークンは秘密の所持を証明するが、汎用的なメソッド認可は提供しない。
ファイルシステムハンドルと防御的なコマンドパスポリシーは実装済みである。明示的なファイルシステム以外の
ケイパビリティ、セッションメモリ／コマンド実行時間の予算、監査イベントは未実装のまま残っている。プレビューと
レスポンスの上限は、すべてのドキュメント操作やデスクトップのスクリーンショットキャプチャを制限するわけではない。非公開のトークン管理、プロセスの
分離、最小権限での実行は、引き続き実用的な封じ込め策である。
