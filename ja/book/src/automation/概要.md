# 自動化の概要

PhotoCraft の自動化には 3 つの入口がある。

1. `photocraft-cli` は、変換、検査、コマンド、バッチ、ドロップレットといった有限のジョブを実行する。
2. `photocraft-cli serve` は、stdio またはループバック TCP 上の JSON lines でヘッドレスセッションを維持する。
3. `photocraft-cli mcp` は、stdio 上で MCP ツールを公開する。対象はプロセス内のヘッドレスセッション、またはデスクトップ制御サーバーへのブリッジのいずれかである。

デスクトップアプリケーションは、`photocraft --control <port>` により認証付きのループバック JSON 制御サーバーを起動できる。このサーバーは、ポインタ／タイプ入力やスクリーンショットを含むエンジンおよび UI の操作を公開する。各 TCP 接続は、いずれかの操作がディスパッチされる前に、設定済みのベアラートークンを提示しなければならない。

すべての編集経路は最終的にコマンドレジストリに到達する。ただし、トランスポートの挙動は同等ではない。UI 固有のメソッドを使えるのはライブブリッジのみであり、ファイル操作は選択されたバックエンドを所有するプロセス内で実行される。

## 安全な運用の前提

- TCP リスナーが不要な場合は、単発の CLI コマンドまたは stdio の MCP を優先する。
- 自動化は、現実的に可能な範囲で最小権限の OS アカウントで実行する。
- デスクトップの制御ポートを常時有効にしない。
- コマンドパラメータ、ファイル名、ドキュメントのメタデータ、ログに秘密情報を含めない。
- ツールの説明やドキュメントの内容は信頼できないものとして扱う。それらは権限を付与しない。

現在のセキュリティ上の制限は [自動化のセキュリティモデル](セキュリティモデル.md) にまとめてある。
