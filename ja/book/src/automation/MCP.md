# MCP

`photocraft-automation` は stdio 上の MCP サーバーを実装しており、バックエンドは 2 種類ある。

- **ヘッドレス:** プロセス内の `Headless` セッションがエンジンを所有し、ファイル I/O を行う。
- **ブリッジ:** `BridgeClient` が、`photocraft --control <port>` で起動したデスクトップアプリケーションへツール呼び出しを転送する。

ヘッドレスサーバーは次のように起動する。

```sh
photocraft-cli mcp --automation-read-root /work/project --automation-write-root /work/project
```

実行中のデスクトップアプリケーションへブリッジするには、アプリと同じ非公開トークンファイルを使う。

```sh
photocraft-cli mcp --bridge 127.0.0.1:7878 --control-token-file /private/path/control.token
```

ツールは、セッション／ドキュメント操作、コマンドの探索と実行、バッチ処理、さらにブリッジ時には UI の検査と制御をカバーする。ツールスキーマは正確性を高めるが、認可の境界ではない。

## セキュリティに関する注意

stdio の MCP はネットワークリスナーを開かない。そのクライアントは、起動時に明示的に付与された
読み取りルートと書き込みルートのみを受け取る。ルートを省略すれば、その権限も付与されない。ブリッジモードは、
いずれかの制御メソッドを呼び出す前にベアラートークンでループバック制御接続を認証し、
デスクトッププロセス側で設定されたルートを使用する。

現行のサーバーは、スコープ付きセッションを発行せず、信頼されたツールと影響の大きいツールを区別しない。認証はトークンの所持を証明するだけであり、認証済みクライアントをドキュメントのみへのアクセスに制限するものではない。外部のポリシー境界を追加しないまま、いずれのトランスポートも信頼できないブローカー、シェル、プロキシ、リモートサービス経由で公開してはならない。

ファイルシステムのケイパビリティは実装済みである。汎用的なツールおよびメソッドのケイパビリティは
引き続き [提案段階](../security/自動化のセキュリティ.md) である。
