# コントリビューション

ソースを編集する前に、[`AGENTS.md`](https://github.com/storytold/photocraft/blob/main/AGENTS.md) と既存の [コントリビューションガイド](https://github.com/storytold/photocraft/blob/main/docs/contributing.md) を読んでください。これらのファイルでは、クリーンルームポリシー、クレートのレイヤー構成、コマンドのチェックリスト、テスト要件、命名、視覚的な検証のルールが定められています。

リポジトリの重要な不変条件には次のものがあります。

- ユーザーに見える挙動は、純粋なシェル／ビューの状態でない限り、エンジンコマンドとして実装する
- 公開されるピクセル経路は 8 ビットのデータや sRGB を前提にできない
- コマンドの実行は、敵対的な入力に対してパニックせずエラーを返さなければならない
- フォーマットに関する作業には、ラウンドトリップ、不正入力、制限のテストを含める
- L0〜L6 の変更は、引き続き WebAssembly 向けにコンパイルできなければならない
- サードパーティのアセットには、寛容なライセンス、隣接するライセンスファイル、`ATTRIBUTION.md` のエントリが必要

## セキュリティに関わるコントリビューション

パーサー、ファイル I/O、シリアライズ、自動化、MCP、制御サーバー、コマンドディスパッチを変更する前に、[脅威モデル](../security/脅威モデル.md) と [信頼境界](../security/信頼境界.md) を読んでください。変更が実装済みの制御策を追加するものなのか、制限を文書化するものなのか、今後の強化を提案するものなのかを明記してください。修正したセキュリティ上の欠陥については、安全なテストが可能であれば必ず回帰テストを追加してください。

Issue、コミット、フィクスチャ、ファズコーパスに、実際に動作するエクスプロイトのペイロード、秘密情報、個人のファイル、ライセンスのないサンプルを含めないでください。未公開の脆弱性については [脆弱性の報告](../security/脆弱性の報告.md) に従ってください。
