# パーサーの堅牢化

パーサーの安全性は「クラッシュしない」ことよりも広い概念である。パーサーは、メモリ、CPU 時間、再帰、出力の膨張、生成するオブジェクトの数にも上限を設けなければならない。

## 実装済みの制御

### PSD/PSB

`photocraft-psd` は、ドキュメントの寸法とチャンネル数の上限を適用し、デコード後のチャンネルデータを制限し、ActionDescriptor のネストとパターンの辺の長さを制限し、デコード後のサイズに関する主要な計算にチェック付き算術演算を使う。テストでは、不正な形式のヘッダー、途中で切れたデータ、プロパティベースで生成した入力、専用のファズターゲットをカバーしている。

### ラスターコーデック

`photocraft-codecs` には、幅、高さ、ピクセル数、デコード時のアロケーションについて設定可能な `Limits` がある。デフォルトのポリシーは有効なすべてのデコーダーに適用され、過大な PNG、PNM、JPEG、TIFF のヘッダーと、ランダム/変異させた入力でテストされている。

### ネイティブフォーマット

`photocraft-format` は、マニフェスト、blob、展開後の合計バイト数に上限を設け、ZIP の構造と展開後のサイズを検証し、CRC とコンテンツハッシュを照合し、サポートしないバージョンを拒否し、ランダムなバンドル/マニフェストでプロパティテストを行う。

## レビューチェックリスト

攻撃者が制御しうるすべての数、オフセット、寸法、長さについて:

1. ファイルのフィールドを切り詰めずに表現できる型にパースする。
2. アロケーションの前にセマンティクス上の制限を検証する。
3. `checked_add`、`checked_mul`、または意図的に安全な飽和比較を使う。
4. スライスする前に、範囲が入力の内側にあることを確認する。
5. デコードしたバイト数、オブジェクト数、再帰を予算に計上する。
6. フォーマット固有のエラーを返す。決してパニックしたり無限ループしたりしない。
7. ゼロ、最大値、最大値 + 1、途中で切れたデータ、矛盾した宣言をテストする。

## 今後の堅牢化

- ネストした PSD リソースと埋め込みオブジェクトの間で共有される、パース全体の予算を定義する。
- サイズの上限内でも極端に断片化したファイルに対して、時間/処理量のカウンターを追加する。
- 再帰的なドキュメント間の関係を含め、ActionDescriptor 以外でもスタックの深さを検証する。
- フォーマット固有の展開率とオブジェクト数についての回帰ケースを追加する。
- 受け入れ可能な最悪ケースの入力を、制約のあるマシンでベンチマークする。
- 最小化したファジングの成果物を、機微でない出所の注記とともに保持する。
