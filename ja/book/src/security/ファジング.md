# ファジングと回帰テスト

PhotoCraft には、信頼できないフォーマットを扱う主要なクレートの隣に、すでに `cargo-fuzz` のワークスペースがある。

| クレート | ターゲット |
|---|---|
| `crates/psd` | `parse`, `descriptor` |
| `crates/codecs` | `decode_any`, `decode_png`, `decode_jpeg`, `decode_tiff`, `decode_exr` |
| `crates/format` | `load` |

メインの CI ワークフローでは、手動で起動するファジングジョブでこれらのターゲットを実行できる。現在、定期実行による継続的なファジングは行っていない。

nightly の Rust と `cargo-fuzz` をインストールした状態で、各クレートのディレクトリからターゲットを実行する。

```sh
cd crates/psd
cargo fuzz run parse
```

通常のテストスイートは、プロパティテスト、構造化された不正形式のケース、途中切れのスイープ、ビット変異、爆弾のようなヘッダー、アーカイブの破損、コマンドの `panic_hunt` によるカバレッジで libFuzzer を補完している。

## セキュリティ上の性質

有用なファズターゲットは、メモリ安全性に関わるクラッシュ以外も検出すべきである。関連する失敗には次のものがある。

- パニックやアボート
- 整数オーバーフローや範囲外アクセス
- 不合理なアロケーションや展開による膨張
- タイムアウト、無限ループ、計算量の急増
- 再帰/スタックの枯渇
- 不正な形式の入力が受け入れられ、不正な内部状態になること
- フォーマット自動判別によるデコードと、フォーマット明示によるデコードの結果の不一致
- ハッシュ/CRC が一致しないにもかかわらず、破損した `.pcraft` の内容が受け入れられること

## コーパスのポリシー

確認された欠陥はすべて、開示とライセンスが許す限り、最小化した恒久的な回帰テストにすべきである。合成した入力か再配布可能な入力のみを保存すること。個人のドキュメント、顧客データ、認証情報、プロプライエタリなアセット、未公開の攻撃用サンプルをコミットしないこと。

回帰テストのエントリには、影響を受けるパーサー、期待されるエラーの種類、リソースの予算、および開示後の Issue/アドバイザリへの参照を記録すべきである。修正が永続的とみなされるには、ファジングで見つかったクラッシュを通常のテストで再現できていなければならない。
