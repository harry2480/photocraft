# 安全なファイル処理

PhotoCraft は、デスクトップアプリ、CLI、ヘッドレス RPC サーバー、MCP サーバーでドキュメントを読み書きする。
リモートの自動操作から渡されるパスは信頼できない相対名であり、明示的に付与されたルートの配下で解決される。

## 実装済み

- フォーマットのローダーは、I/O エラーや不正な形式のデータに対して構造化されたエラーを返す。
- `.pcraft` の ZIP 読み込みでは、アーカイブのオフセット、エントリのサイズ、CRC、コンテンツハッシュ、設定された展開後サイズの予算を検証する。
- ラスターおよび PSD のローダーは、主要なピクセルのアロケーションの前にパース/デコードの制限を適用する。
- ネイティブの `.pcraft` 保存では、該当するストアの経路で一時ファイル + リネームのパターンを使う。
- `AuthorizedWorkspace` は、リモートの自動操作のために、互いに独立した読み取り用と書き込み用のディレクトリ
  ケイパビリティを保持する。
- 絶対パス、親ディレクトリへのトラバーサル、代替の区切り文字、ドライブ/デバイス/ストリームのプレフィックス、
  Windows の予約デバイス名、空または `.` のコンポーネント、リンクによる脱出は、ファイルへの作用が起きる前に
  拒否される。
- 存在しない出力ファイルは、その親ディレクトリが書き込みルート配下にすでに存在する場合にサポートされる。
  自動操作は、呼び出し元が指定したディレクトリツリーを作成しない。
- ケイパビリティ I/O にまだ移行していない、ファイルシステムを扱うエンジンコマンドは、自動操作に対しては
  フェイルクローズする。信頼されたローカルの CLI サブコマンドと、ユーザー操作によるデスクトップの
  ファイルピッカーは、意図されたアンビエントな権限を維持する。

## 既知の制限事項

- ディレクトリ形式の `.pcraft` バンドルが、リンクの差し替えや TOCTOU（チェック時と使用時の差）競合に耐性を持つことは文書化されていない。
- ルートの付与はプロセス起動時の設定であり、ドキュメント単位の付与ではない。
- 汎用的なメソッドケイパビリティと、構造化されたファイルシステム監査イベントは実装されていない。
- 付与されたルート内に既存のハードリンクは、信頼されたルートの内容として扱われる。パスのポリシーからは
  それがどのように作られたかを推測できない。

## ケイパビリティベースの設計

文字列のサニタイズを繰り返すよりも、オープン済みのディレクトリケイパビリティやワークスペースハンドルを優先する。

```text
AuthorizedWorkspace
  - open_document(relative_path)
  - save_document(relative_path)
  - export_render(relative_path)
```

ハンドルは起動時の明示的な付与から作られ、読み取り/書き込みの権限を区別して保持し、絶対パスやルート外に
抜け出すパスを拒否し、保持しているディレクトリケイパビリティを基準に操作を行う。存在しないターゲットは
安全に正規化できないため、新しいファイルにはルート内に既存の親ディレクトリが必要である。

## 設計要件

- 正規化だけでは不十分である。検証後にリンクが変わる可能性がある。
- ポリシーは、プラットフォームの API が許す範囲で、ハンドルと相対コンポーネントに対して適用すべきである。
- 読み取りと書き込みには別個のケイパビリティを持たせるべきである。
- 置換、新規作成、切り詰め、ディレクトリ作成のセマンティクスは明示的でなければならない。
- ログにはファイルの内容を含めず、非公開のフルパスの露出を最小限にすべきである。
- テストでは、対応プラットフォーム上で `..`、絶対パス、区切り文字の混在、大文字小文字の扱い、シンボリックリンク/ジャンクション、存在しないターゲット、差し替えによる競合をカバーすべきである。

OS アカウント、VM、コンテナ、サンドボックスによる隔離は、信頼できない自動操作や、汎用的なメソッド
ケイパビリティでまだカバーされていない制御に対する多層防御として、引き続き適切である。
