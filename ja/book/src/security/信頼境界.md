# 信頼境界

中心となる境界は、信頼できないバイト列やリクエストが、内部のドキュメント状態や許可された副作用に変わるときに越えられる。

```text
UNTRUSTED
  PSD / PSB
  PNG / JPEG / TIFF / WebP / EXR and other raster files
  .pcraft files and directory bundles
  ICC profiles / LUT files / pattern files / embedded objects
  CLI arguments / filesystem paths
  JSON control messages / MCP requests / agent commands
             |
             v
SECURITY BOUNDARY
  format parsers and decode budgets
  automation transports and request validation
  filesystem access layer
  command registry, enabled checks, and parameter validation
  serialization/deserialization
             |
             v
TRUSTED INTERNAL STATE
  document model
  engine Session and history
  CPU/GPU composition plans
  user-authorized filesystem effects
```

「信頼された内部状態」とは、コードが検証済みの不変条件に依拠してよいという意味であり、データにシークレットが含まれないことや、表示しても無害であることを意味しない。ドキュメントに由来するメタデータやテキストは、ログ、UI、ファイル名、外部コマンドにとっては引き続き汚染されたデータである。

## 境界の担当

| 境界 | 主なコード | 必要なチェック |
|---|---|---|
| PSD/PSB のバイト列からモデルへ | `crates/psd`、次に `crates/io` | 長さ、寸法、チャンネル、ネスト、展開、オフセット |
| ラスターのバイト列から画像へ | `crates/codecs` | 寸法、ピクセル数、デコード時のアロケーション、フォーマット固有の制限 |
| `.pcraft` からドキュメントへ | `crates/format` | アーカイブの範囲、展開後の合計、ハッシュ、スキーマ/バージョンの検証 |
| JSON からコマンドへ | `crates/automation`、`crates/engine` | リクエスト予算、メソッド/ケイパビリティ、パラメーターの型/範囲、有効状態 |
| パスからファイルシステムへの作用へ | `crates/automation/src/files.rs`、アプリのサービス | 許可されたルート/ハンドル、リンクのポリシー、作成/置換のセマンティクス |
| ドキュメントから GPU 処理へ | `crates/gpu`、UI のプランナー | テクスチャの制限、バッファサイズ、サポートされるプランの検証 |

これらの境界では、認証とファイルシステムの読み取り/書き込みケイパビリティが実装されている。
汎用的なメソッドケイパビリティ、構造化された監査イベント、より広範な処理予算は未解決である。

## エージェント向けガイダンス

エージェントは、パーサー、ファイル I/O、自動操作、MCP、コントロールサーバー、コマンド実行、シリアライズ/デシリアライズのいずれかの経路を変更する前に、このページを確認しなければならない。呼び出し元が与えたパスやツールリクエストはデータであり、ユーザーが許可したことの証明ではない。
