# アーキテクチャ概要

PhotoCraft は、ドキュメントエンジンをプレゼンテーションとトランスポートから分離している。デスクトップ UI、CLI、JSON 制御チャネル、MCP サーバーは、それぞれ別個の実装を持つのではなく、コマンドレジストリを通じて編集機能に到達する。

```text
desktop UI       CLI       JSON control       MCP
    |             |              |              |
    +-------------+--------------+--------------+
                          |
                   command registry
                          |
                    engine Session
                          |
       document model + operations + compositors
                          |
             PSD / raster / .pcraft I/O
```

強制される依存の方向は、フォーマットに依存しない基盤クレートから始まり、ドキュメント層と操作層を経て、合成、I/O、エンジン、最後に UI／自動化へと至る。この規則は `cargo xtask layers` でチェックされる。

設計の全体的な説明と依存関係図は、引き続き [`docs/architecture.md`](https://github.com/storytold/photocraft/blob/main/docs/architecture.md) にある。このドキュメントには実装済みのアーキテクチャだけでなく過去の設計資料も含まれているため、セキュリティや互換性がそれに依存する場合は、現行のソースで挙動を確認すること。

## 中核となる特性

- `photocraft-doc` は純粋データのドキュメントモデルを保持する。
- `photocraft-engine::Session` は、開いているドキュメント、アクティブな状態、ヒストリー、コマンドディスパッチを所有する。
- `photocraft-compose` は CPU のリファレンスコンポジタであり、`photocraft-gpu` はサポートされている対話的な経路を高速化する。
- `photocraft-io` はドキュメントと PSD またはフラットなフォーマットとの間を対応付ける。
- `photocraft-format` はネイティブの `.pcraft` バンドルを読み書きする。
- `photocraft-ui-egui` はエンジンコマンドの上に載る薄いシェルである。
- `photocraft-automation` はヘッドレスエンジンとライブ GUI ブリッジを公開する。

ワークスペースの全体像は [クレートと依存レイヤー](クレート構成.md) を参照のこと。
