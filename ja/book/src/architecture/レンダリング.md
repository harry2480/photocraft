# レンダリング

PhotoCraft には、役割の異なる 2 つのコンポジタがある。

- `photocraft-compose` は CPU コンポジタであり、エクスポートとテストで使われる正しさのオラクルである。
- `photocraft-gpu` は、サポートされるキャンバス合成を wgpu を通じて計画・実行する。

対話的なキャンバスは、プランナーがドキュメントを表現できる場合に GPU 経路を使う。サポートされないケースは CPU 合成にフォールバックする。現在のドキュメントでは、マルチチャンネルのドキュメントと GPU テクスチャの上限を超える領域がフォールバックのケースとして挙げられている。

`photocraft-raster` のピクセルストレージは、公開 API に 8 ビット専用の経路を設けるのではなく、実行時のサンプル深度をサポートする。カラーモードとプロファイルはドキュメントのデータであり、色変換は暗黙の sRGB として扱うのではなく `photocraft-cms` で行う。

## 検証

GPU の変更には、CPU オラクルに対するパリティチェックが必要である。UI の変更には、オフスクリーンのスナップショット例または制御チャネルのスクリーンショットを使った、実際にレンダリングされた画像が必要である。

```sh
cargo run -p photocraft-ui-egui --example snapshot
cargo test -p photocraft-gpu
```

パフォーマンスが重要な作業では、フレームごとのサーフェス全体の処理を避け、タイル単位で処理し、空のタイルをスキップし、リビジョンごとにキャッシュすべきである。現在のコマンドとベンチマークの入口は [`docs/development.md`](https://github.com/storytold/photocraft/blob/main/docs/development.md) に記載されている。

GPU 処理はセキュリティサンドボックスではない。寸法、デコード済みバッファ、シェーダー、コマンドパラメータは、リソースの作成やディスパッチの前に検証しなければならない。
