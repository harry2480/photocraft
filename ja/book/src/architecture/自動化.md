# 自動化のアーキテクチャ

PhotoCraft は同じエンジンを複数のトランスポートを通じて公開している。

```text
photocraft-cli commands/run/batch
             |
MCP stdio ---+--> photocraft-automation::Headless --> engine Session

MCP bridge --> BridgeClient --> 127.0.0.1 control server --> UI ControlRequest

JSON-lines stdio/TCP --> rpc::respond --> Headless::handle --> engine Session
```

ヘッドレスのファイル操作は `crates/automation/src/files.rs`、RPC のディスパッチは `crates/automation/src/rpc.rs`、MCP ツールの登録は `crates/automation/src/server.rs`、ライブクライアントは `crates/automation/src/bridge.rs` に実装されている。デスクトップの TCP リスナーは `apps/photocraft/src/control_server.rs` である。

制御用およびヘッドレス用の TCP リスナーはループバックアドレスに制限されている。stdio の MCP は待ち受けネットワークソケットを持たないが、MCP プロセスはそれを起動したユーザーのファイルシステム権限で動作する点に変わりはない。

ループバックは認証ではない。TCP トランスポートはベアラートークンを要求し、リクエストバイト数、
バッチステップ数、アクティブ接続数の制限を課す。リモートのファイルメソッドは、読み取りと書き込みで
独立したディレクトリケイパビリティを持つ `AuthorizedWorkspace` を使用する。パスは設定されたルートからの相対パスであり、
該当するルートが存在しない場合はフェイルクローズする。汎用的なメソッド単位のスコープ、クライアント識別、
暗号化、操作予算は実装されていない。これらの面を公開または拡張する前に、
[自動化のセキュリティモデル](../automation/セキュリティモデル.md) と
[自動化のセキュリティ](../security/自動化のセキュリティ.md) を参照のこと。
