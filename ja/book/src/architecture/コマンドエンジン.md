# コマンドエンジン

ユーザーに見えるすべての編集アクションは、`crates/engine/src/*_cmds.rs` 内のコマンド仕様として表現され、`crates/engine/src/commands.rs` で登録される。仕様は ID、ラベル、メニューパス、ショートカット、パラメータのドキュメント、有効判定（enabled 述語）、および `run` 実装を提供する。

```text
caller
  |
  | command id + JSON parameters
  v
command registry -- enabled/parameter checks --> command run closure
                                                   |
                                                   v
                                           Session + one history step
```

デスクトップ UI、CLI、制御プロトコル、MCP ツールはすべてこのレジストリへディスパッチする。純粋なビュー／ウィンドウの状態は例外であり、UI シェルのコマンドテーブルで扱われる。

## 入力の契約

コマンド境界において、コマンドパラメータと現在のドキュメント状態は信頼できない。実装は、欠落、型の誤り、範囲外、または矛盾したパラメータに対して `Err` を返さなければならない。入力から導出された値が、チェックされていないインデックス参照、除算、確保サイズの決定、パニック経路に到達してはならない。

無視指定（ignored）の統合テスト `crates/engine/tests/panic_hunt.rs` は、敵対的なパラメータでコマンドを実行する。変更したコマンドには、対象を絞ったグレースフルな失敗のテストも必要であり、次のコマンドで検証すべきである。

```sh
cargo test -p photocraft-engine
cargo test -p photocraft-engine --test panic_hunt -- --ignored
```

コマンド作成の正確なチェックリストは、既存の [コントリビューションガイド](https://github.com/storytold/photocraft/blob/main/docs/contributing.md) で管理されている。

## セキュリティ境界に関する注意

レジストリはコマンドの挙動を検証するが、現在の自動化トランスポートはコマンド単位のケイパビリティを提供しない。コマンドディスパッチに到達した MCP または制御クライアントは、実行時の `enabled` 述語が許可する限り、公開されている任意のコマンドを要求できる。ケイパビリティの強制は [提案中の自動化の強化策](../security/自動化のセキュリティ.md) であり、実装済みの制御策ではない。
