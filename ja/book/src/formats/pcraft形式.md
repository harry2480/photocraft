# `.pcraft` フォーマット

`photocraft-format` は、ネイティブのロスレスなドキュメントを ZIP アーカイブまたはディレクトリバンドルとして保存する。主なエントリは次のとおり。

```text
manifest.json
tiles/<blake3>.zst
blobs/<blake3>.zst
thumb.png
composite/preview.png
```

マニフェストはバージョン管理されており、ドキュメントツリーを記述する。タイルと blob はコンテンツアドレス方式で格納される。ローダーは ZIP エントリの境界と CRC を検証し、ドキュメントの内容についても、保存されたハッシュを使って不一致や破損したタイル／blob を検出する。サポートされない新しいフォーマットバージョンは明示的に失敗する。

## 実装済みの読み込み制限

デフォルトの `LoadOptions` は次の上限を適用する。

| 制限 | デフォルト |
|---|---:|
| `manifest.json` | 256 MiB |
| 展開後の blob 1 つ | 1 GiB |
| 展開後のタイルと blob の合計 | 16 GiB |

ZIP リーダーは呼び出し側が指定した上限で展開量を制限し、暗号化されたエントリやサポートされない圧縮方式を拒否し、オフセットをチェック付き演算で検証し、CRC や宣言サイズの不一致を拒否する。破損テストとプロパティテストは、切り詰め、バイトの改変、内容の欠落、不正なマニフェスト、過大なサイズ、ランダムなバイト列をカバーしている。

これらのデフォルトは意図的に有限としているが、リソースの限られたシステムでは依然として高コストになりうる。今後の強化として、状況に応じた予算と、エントリ数、ドキュメントの複雑さ、累積作業量に対する明示的な制限を追加し、ディレクトリバンドルをシンボリックリンクや置き換えの競合に対してテストすべきである。

`photocraft-doc` にフィールドが追加された場合、`photocraft-format` はネイティブ保存で新しい状態が黙って失われないよう、対応するマニフェストと変換の更新を意図的に要求する。
