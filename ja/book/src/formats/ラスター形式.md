# ラスターフォーマット

`photocraft-codecs` は、フラットな画像のためのフォーマット判定、ケイパビリティ宣言、デコード制限、メタデータ処理、エンコードを提供する。デフォルトビルドでは、PNG、JPEG、TIFF、WebP、GIF、BMP、TGA、ICO、Netpbm/PFM、QOI、OpenEXR、Radiance HDR の読み書きサポートを宣言している。AVIF エンコードはオプションであり、AVIF デコードは現行のクレートでは実装されていない。

サンプル深度、チャンネル構成、アルファ、ICC、EXIF、XMP、DPI、アニメーションの挙動といったケイパビリティの詳細は `crates/codecs/src/format.rs` で定義されている。ファイル名の拡張子だけから忠実性を推測してはならない。

## 実装済みのデコード制限

`DecodeOptions::default()` は、デコード済みピクセルを確保する前に `Limits` を適用する。

| 制限 | デフォルト |
|---|---:|
| 最大幅 | 262,144 ピクセル |
| 最大高さ | 262,144 ピクセル |
| 最大ピクセル数 | 268,435,456 ピクセル |
| デコード時の最大確保量 | 2 GiB |

フォーマットアダプタは、PNG、TIFF、WebP、および `image` ベースのデコーダに互換性のある確保制限を渡し、その他の実装は寸法／バッファの明示的なチェック付き検証を行う。テストは、ボム的なヘッダー、切り詰め、ビット反転、ヘッダーの上書き、ランダムなデータをカバーしている。

`Limits::none()` は、ポリシーを緩める明確な理由がある呼び出し側のために存在する。表現可能なメモリサイズによる制約は残るが、デフォルトのリソースポリシーは取り除かれるため、信頼できない入力に使ってはならない。

アニメーションを含むコンテナは、現行のコーデック API では 1 枚のデコード済みフレームとして表現される。現在の挙動については [`crates/codecs/README.md`](https://github.com/storytold/photocraft/blob/main/crates/codecs/README.md) とソースのケイパビリティ宣言を参照のこと。
