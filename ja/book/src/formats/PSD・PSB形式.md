# PSD と PSB

`photocraft-psd` は、Adobe の公開 PSD 仕様に基づくスタンドアロンのクリーンルーム実装のリーダー兼ライターである。PSD バージョン 1 と PSB バージョン 2 をサポートし、ラウンドトリップの忠実性のために未知のブロックを保持し、チャンネルデータを遅延デコードする。

パーサーは、このクレートが扱う 4 種類すべての PSD 圧縮方式を受け付け、`photocraft-io` が `photocraft-doc` へ対応付ける前の段階でフォーマットレベルの構造を表現する。現在の公開 API と忠実性に関する挙動は [`crates/psd/README.md`](https://github.com/storytold/photocraft/blob/main/crates/psd/README.md) に記載されている。

## 実装済みのパーサー保護

現行のソースは、いくつかの明示的な制限を強制している。

- ドキュメントの幅と高さ: それぞれ最大 300,000 ピクセル
- ドキュメントのチャンネル数: 最大 56
- レイヤーのチャンネル数: 最大 64
- デコード済みチャンネルデータ: 1 つのデコードレイアウトにつき最大 2 GiB
- ActionDescriptor のネスト: 最大 64 レベル
- パターンの辺長: 最大 30,000 ピクセル
- 行数とデコード長の演算にはチェック付き演算を使用

不正入力テスト、プロパティテスト、`cargo-fuzz` のターゲットが、メインのパーサーと ActionDescriptor パーサーをカバーしている。これらの制御策はリスクを下げるが、あらゆる悪意あるファイルに対してパーサーが安全であることや、すべての埋め込みオブジェクトにわたる総作業量が制限されていることを証明するものではない。

## 残っている堅牢化

優先事項には、PSB と埋め込みオブジェクトのファズコーパスの拡充、累積アロケーションと解析時間の計測、ネストしたすべての長さに予算が設定されていることの確認、最小化したクラッシュ入力を回帰用フィクスチャとして保持することが含まれる。[ファジングと回帰テスト](../security/ファジング.md) を参照のこと。
