# リリースのセキュリティ

PhotoCraft のリリースワークフローは、`release` ブランチからプラットフォームごとのパッケージと GitHub Release の下書きをビルドする。正となる手順は [`docs/releasing.md`](https://github.com/storytold/photocraft/blob/main/docs/releasing.md) である。

## 実装済みのワークフロー要素

- macOS と Windows 向けに、プラットフォーム固有の署名／公証のステップがある
- 署名用シークレットは GitHub の `release` 環境にスコープされている
- リリース成果物には `SHA256SUMS.txt` が含まれる
- 最終リリースジョブは `contents: write` を受け取り、ビルドジョブはより狭いアクセス権を使う
- 成果物は、メンテナーが公開するまで下書きリリースのまま残る

署名は条件付きである。署名用の素材が利用できない場合、ワークフローは警告を出しつつ未署名の成果物を生成しうる。利用者とメンテナーは、すべてのリリースが署名済みだと仮定せず、ジョブのサマリーと成果物の署名を確認しなければならない。

## 今後の強化

- リリースごとに機械可読な SBOM を生成する
- ソースコミットとワークフローに紐づいたプロベナンス／アテステーションを公開する
- リリースのメタデータで署名状態を明示する
- 公開前にチェックサム、署名、公証、インストーラーの挙動を検証する
- アクションのピン留めとリリースツールのプロベナンスをレビューする
- 鍵のローテーションと侵害時の対応を文書化する

ビルド、署名、下書き、公開、デプロイはそれぞれ別の状態である。ビルドが成功したことを、リリースが公開されたと報告してはならない。
