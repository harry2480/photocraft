# 依存関係

Cargo の依存関係は `Cargo.lock` で固定されており、通常のワークスペースのビルド、テスト、clippy、WebAssembly のジョブで検証される。パーサーと GPU の依存関係は、攻撃者が制御するデータを処理したりネイティブドライバとやり取りしたりするため、追加のレビューに値する。

## リポジトリの現状

現在のツリーには、`cargo-deny` のポリシーファイル、`cargo-audit` のジョブ、あるいはそれに相当する依存関係アドバイザリのワークフローは存在しない。設定と CI での実績が揃うまで、依存関係の監査を実装済みと記述してはならない。

## 提案するチェック

```sh
cargo audit
cargo deny check
```

将来の `deny.toml` はメンテナーがレビューし、許容するライセンス、アドバイザリポリシー、ソースの規則、重複バージョンのポリシーを記述すべきである。アドバイザリの例外には、責任者、理由、補完的な制御策、有効期限／レビュー日が必要である。CI ツールと GitHub Actions もバージョンを固定し、依存関係としてレビューすべきである。

依存関係の変更では、そのクレートが必要な理由、信頼できない入力を処理するかどうか、unsafe／ネイティブコードへの露出、サポートするターゲット、メンテナンス状況、ライセンスの互換性を記録すべきである。ソースレビューをスキャナーの結果で置き換えてはならない。
