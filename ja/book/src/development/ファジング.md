# ファジング

ファジングの手順、現在のターゲット、セキュリティ特性、コーパスのルールは [ファジングと回帰テスト](../security/ファジング.md) で管理されている。

既存のファズ用ワークスペースは、`cargo-fuzz` が nightly の Rust とサニタイザーのインストルメンテーションを使うため、意図的にメインの Cargo ワークスペースから分離されている。例:

```sh
rustup toolchain install nightly
cargo install cargo-fuzz --locked
cd crates/codecs
cargo +nightly fuzz run decode_any
```

クラッシュを再現し、最小化し、決定的な回帰テストを追加してから修正すること。時間を区切ったファジングで何も見つからなかったとしても、それはその実行についての証拠にすぎず、パーサーが安全であることの証明ではない。

メインの GitHub Actions ワークフローは現在、`fuzz` 入力を指定して手動でディスパッチした場合にのみファジングを実行する。定期実行やホスト型の継続的ファジングは今後の課題である。
