# テスト

テストはソース変更のゲートである。開発中は関連する最小範囲のパッケージテストを選び、その後、変更したレイヤーに応じたリポジトリのゲートを実行する。

```sh
cargo test -p <package>
cargo clippy -p <package> --all-targets -- -D warnings
cargo xtask layers
```

L6 以下の変更では `cargo xtask wasm` も実行する。コマンドの変更には、無視指定（ignored）の敵対的テストが必要である。

```sh
cargo test -p photocraft-engine --test panic_hunt -- --ignored
```

フォーマットの変更には、正当なラウンドトリップ、正確な境界値、切り詰め、不整合な長さ、不正な構造、確保／展開の制限ケースを含めるべきである。ピクセルの挙動は、該当する 8 ビット、16 ビット、32 ビットの深度で検証すべきである。

UI の変更には、オフスクリーンのスナップショット例または制御チャネルのスクリーンショットによる、レンダリング結果の証拠が必要である。ビルドの成功や HTTP レスポンスは視覚的な検証ではない。

ドキュメントの変更は次のコマンドで検証する。

```sh
mdbook build book
```

内部の Markdown リンクと `SUMMARY.md` のすべてのリンク先もチェックすべきである。ドキュメントのワークフローは CI でクリーンな mdBook ビルドを実行する。
